How conversion works

The browser DOMParser builds an XML tree. We walk each element, map attributes with your prefix, fold text/CDATA, and emit arrays when the same tag repeats.

<user id="1">Ada</user>
→ {"user":{"@id":"1","#text":"Ada"}}

Why @ and #text?

  • Avoids collisions with child names
  • Used by FreeFormatter-style tools
  • Easy to round-trip later
  • Clear for mixed content
  • Stable for unit tests

XML vs JSON

  • XML: attributes + mixed content
  • JSON: objects / arrays / scalars
  • Use JSON for REST & JS apps
  • Keep XML for SOAP / XSD
  • This tool is one-way (XML→JSON)

Attribute & text mapping

XML attributes have no direct JSON twin. By default they become properties like @id so they never clash with a child element named id. When an element has both children and text, the text is stored under #text (configurable). Pure-text elements usually collapse to a plain string for cleaner output — the same approach used by FreeFormatter and OpenFormatter-style converters.

Arrays, CDATA & namespaces

  • Repeated siblings (e.g. multiple <item>) become a JSON array when auto-array is on.
  • CDATA is treated as text content (quotes and markup stay literal).
  • Namespaces are kept in the tag name by default (dc:title). Enable “Strip XML namespace prefixes” if you want bare local names.
  • Comments and processing instructions are ignored.

Privacy

Parsing and conversion run entirely with the browser’s DOMParser and JavaScript. Your XML never leaves the device — ideal for internal configs, customer payloads, and API samples.

FAQ

Why did conversion fail?

XML must be well-formed: a single root, matching end tags, and properly escaped & < >. The status line shows the DOMParser error message when parsing fails.

Can I change @ and #text?

Yes — set Attribute prefix and Text node key before converting. Keep them consistent with whatever your application already expects.

Do numbers stay as strings?

With “Coerce numbers / booleans / null” enabled, values like 42, true, and null become JSON number / boolean / null. Turn it off to keep every text value as a string.

Is this bidirectional?

This page focuses on XML → JSON. Going back to XML needs a separate mapping (and often loses order/comments). Use a dedicated JSON→XML tool if you need the reverse.

Is my data uploaded?

No. Conversion is 100% client-side. Closing the tab clears the editors.
